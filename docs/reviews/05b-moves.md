## Content, drawing and accessibility

The four mixer rows were checked against `motorPlacements`, the body-to-scene quaternion signs,
and the motor, propeller, flight-controller and intro lessons. Throttle raises all four; right
roll raises 3/4; forward pitch raises 1/3; right yaw raises the CCW pair 2/3. Positive roll drops
the right side, positive pitch drops the nose, and positive yaw turns the nose toward +x from
its initial −z direction. These coefficients also match the official
[Betaflight Quad X mixer](https://github.com/betaflight/betaflight/blob/master/src/main/flight/mixer_init.c).
No reversed motor pair or rotation axis was found. The implementation correctly uses negative x
and y rotation axes, correcting the implementation plan's erroneous positive-axis prose.

The controller models rates, rather than commanding an angle: held sticks continue rotation;
centred sticks stop it without seeking level. P/I correction restores a knocked attitude, and
feed-forward balances rotational drag while holding a command. Throttle gives a capped height
hint, not flight. The copy agrees with the linked lessons and the agreed simplifications.
The code's reference to Betaflight “I term relax” is an analogy: actual
[I-term relax](https://betaflight.com/docs/wiki/guides/current/I-Term-Relax-Explained) inhibits
accumulation during manoeuvres, rather than universally resetting the integral whenever a stick
is nonzero. This implementation detail is not presented as a tuning lesson to the learner.

Demand rendering wakes on sticks, Gust and Level. Independent WebGL draw-call instrumentation
stayed at 180 across two initial idle samples, and at 15,816 across two samples after a gust
settled. Motor arcs have no independent invalidation loop. No surviving route timer, duplicate
StrictMode motion loop or console error was observed. Continued rendering in finding 1 follows
the incorrectly retained command, rather than an unconditional frame loop.

The four native ranges have accessible names, bounds, orientation and directional value text.
Keyboard changes and spring-back on key release work; throttle remains where placed. Focus is
drawn on the corresponding pad and axis. Step changes update `aria-current` and the polite live
region; the changing gyro table does not flood a live region. The fallback keeps the lesson and
hides sticks/readouts. Initial reduced motion suppresses demos and Show me explicitly runs them;
live changes fail as described below. At 375 × 667 with ordinary text, the pinned drawing and
both sticks remain visible at the footer, and the sticks sit below the canvas. At 320 px and
200% text there is zero horizontal page overflow, but that does not establish usability:
findings 4 and 5.

## Architecture and test quality

New flight calculations/store code is plain TypeScript; new 3D code imports no `content/`.
Cross-feature imports added for flight/model functionality use public indexes, with runtime
three.js remaining behind the lazy viewer. The existing explorer type import from the internal
`drone-viewer/DroneViewer` file still violates the literal index-only rule, but predates this
branch and creates no new runtime dependency. No runtime dependency or external model was added.
The affected product, surface, architecture, scope and roadmap docs were updated; 05b correctly
remains in review. The commit subjects follow Conventional Commits.

The tests meaningfully establish mixer signs, rotation directions, finite integration, routes,
progress and basic interaction. Several assertions are too narrow to establish their titles:
demo cancellation cancels before the first key or overwrites the same axis; it does not test
taking the other stick after a demo starts. The gyro table test never advances the model or
asserts changed numbers. The readout test accepts either old or new early data, so does not prove
the stated update limit. The browser Level test checks motor highlights, not upright attitude;
the roll browser test checks speeds, not the rendered pose. The phone test checks rectangles in
the viewport, and the reflow test checks overflow, without testing control separation or readable
space below sticky elements. Reduced-motion tests set the preference before load. The fixes
should add focused regressions for the actual failures below.
